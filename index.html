    Which matching mode should I use?
    Exact: look for the same written code

    total = price + 5
    sum = cost + 9

    Different names and numbers do not match. Good for direct copying with formatting changes.

    Normalised: look past renamed variables

    total = price + 5
    sum = cost + 9

    These can match after consistent renaming and replacing literal values. Operators, keywords and member names still matter. x + x differs from a + b.

    Neither mode understands every possible rewrite. Normalised matches can also be coincidental; inspect the evidence.

    What does the similarity percentage mean?

    Score = 100 × (covered tokens in A + covered tokens in B) ÷ (total tokens in A + total tokens in B). A token is covered when it belongs to a contiguous cross-file match at least as long as your minimum. Overlapping matches count only once. Empty token streams score 0%.

    This is lexical comparison, not semantic equivalence. Reordered statements, rewritten logic and different languages may reduce the score. Normalisation can increase coincidental matches. Compare programs in the same language for meaningful results. Language-aware tokenisation handles Python and C-style comments, Unicode names, numeric literals and C++ raw strings. JavaScript regular expressions use a context heuristic. Python f-strings and JavaScript templates are kept verbatim to preserve their embedded code. This is not a full language parser; Python indentation and scope resolution are not modelled. Normalised identifier numbering follows first occurrence within each file, so declaration reordering can reduce matches.
